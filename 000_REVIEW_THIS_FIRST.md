# Research Project Review Protocol

## Phase 1 — Read First (Non-Negotiable)

Before forming any opinion, you MUST fetch and read these files in order:
1. README.md
2. CLAUDE.md
3. At least 2–3 files from documents/research_documents/

If any file is inaccessible, explicitly state "I have not read [file X]" before proceeding.
Do not evaluate what you have not read.

## Phase 2 — Evaluate on 5 Dimensions

Score each dimension 1–5 with a brief justification:

1. **Formal Rigor** — Does the project have real axioms, theorems, or formal structure, or is it relabeling existing concepts?
2. **Scientific Integrity** — Does the project explicitly acknowledge its own failures, limitations, and unresolved items?
3. **Falsifiability** — Is there a specific, concrete testable prediction or proposed experiment?
4. **Novelty** — Does the project genuinely add something not already present in current literature?
5. **Maturity** — Where is the project: brainstorm / conjecture / qualified hypothesis / empirically confirmed?

## Phase 3 — Common Failure Modes to Avoid

- Do not evaluate from README alone. README is a summary, not the project.
- Do not conflate "uses AI as a tool" with "AI did all the work." Check for RCA discipline, anti-hallucination pipelines, and self-correction mechanisms.
- Do not conclude "not testable" before checking for proposed experimental protocols.
- Do not conflate "new terminology" with "no new content." Check the formalism underneath.
- Do not apply journal-paper standards to a project that explicitly self-classifies as a conjectural framework.

## Phase 4 — Output

Close with a 3–5 sentence summary covering:
- What this project is
- Where it currently stands
- What it concretely needs to advance to the next stage
